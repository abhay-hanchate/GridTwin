# Audit, 10 October 2026

A read-only check of the data, the models, the engine and the API, and a list of what the backend has that the
dashboard cannot show. Nothing was changed to produce it. Everything below was measured on this checkout; the scripts
are described in each section so the checks can be repeated.

**Status of the working tree during the audit:** the branch `v2/finish` has uncommitted changes (the redesigned
dashboard, the planning tools, the new street and calendar routes, and the grid-voltage history fix described in
finding 2). The precomputed results in `data/results/v2` were being regenerated for that code when the audit ran.

## 2. Findings

| # | Severity | Finding |
| --- | --- | --- |
| 1 | High | **The street animation draws the wrong wires for the switching fix.** Switching removes one wire and adds another, which re-numbers 68 wire slots. `street_payload` draws the layout of the original street but labels flows with the switched street's wire numbers, and 30 of 96 nodes sit elsewhere in the switched topology. Home voltages are unaffected (they are by home). |
| 2 | High (fixed in the working tree, not committed) | **The live app trained on an incomplete file.** The older committed Mathura files miss all of 2020, so March and April had no voltage history (the "yesterday's voltage" input was `NaN`, passed silently to the model) and the history was 56% to 65% empty. March was 8.1 V off and April's daily shape correlated at 0.48. The app now uses the full record, three small files are allowed into git, and the proxy never returns `NaN`. Every precomputed number changes with it. |
| 3 | Medium | **The dashboard draws raw probabilities, while gate G8 passes on the calibrated ones.** The API returns `calibration.calibrated`; no page uses it. The note under the chart says the chances are "slightly better than the historical average" because of the calibrated result. |
| 4 | Medium | **Solar gates G2 and G3 cannot be re-run from this checkout.** The seven multi-model day-ahead files (`data/raw/dayahead_<model>_mathura_2024_2025.json`) are not present, so `test_real_run_passes_gates_g2_and_g3` fails with a `KeyError` instead of a clear skip. G3's own score does reproduce from the committed table. The comparison value for the first model (0.0396) could not be reproduced (a recomputation on the same hours gave 0.053, probably a different hour alignment), so the size of the improvement is not independently confirmed. |
| 5 | Medium | **Several documents and files describe the old site or old numbers.** `data/results/results.json` predates the demand and G8 re-runs (it still says G8 fails and G4 8.4%); the README says about 350 Python and 74 dashboard tests (now 355 and 96) and "Lighthouse 100, about 79 KB of JavaScript" (about 107 KB gzipped now, not re-measured); `docs/DEMO_SCRIPT.md` and the project document describe demo days, a Home tab and a connection-check form. |
| 6 | Medium | **Live demand anchoring is inactive.** The UP state-demand history was never downloaded and no live demand has ever been recorded, so live forecasts run in "pattern only" mode (the README says so). The drift monitor has one logged day and has never completed a comparison, so it has written no warning state. |
| 7 | Low | **A date outside the forecast archive is accepted and fails later.** `/risk?date=2024-05-15` answers 202, and the job then fails with "no solar forecast for 2024-05-15; available 2025-01-01 to 2025-12-31". The range is known (`/calendar`), so a 404 up front would be cleaner. |
| 8 | Low | The removed `/api/run` answers `{"detail": "Not Found"}` (JSON, but not the v2 error shape). |
| 9 | Low | **Wire flows in the street picture are estimates** from each home's net power, and leave out battery charging and the extra Volt/Watt reduction. The page says the flows are estimated; the battery and Volt/Watt exclusions are only in the code comment. |
| 10 | Low | **Hindi has no bundled Devanagari font.** It renders with the device's font (it did here); a device without one would show empty boxes. |
| 11 | Low | The Vite chunk named `charts` now holds only the font stylesheet; the name is a leftover. `data/results/v2` holds cached files from older code versions that nothing can reach. |

## 3. What the backend has that the dashboard cannot show

### 3.1 Returned by the API but never drawn

| Where | Data | Why it matters |
| --- | --- | --- |
| `/risk` | `shares` for every limit (over-voltage, under-voltage, line overload, transformer overload) | Only the largest is used, for one word in the headline |
| `/risk` | `window_risk`: the chance of an unsafe spell of at least 15 minutes, 1 hour, 3 hours, 24 hours | Operators care about spells, not single quarter hours |
| `/risk` | `calibration.calibrated` and `held_out_skill` | See finding 3 |
| `/headroom` | `strict_kw`: extra kW with the whole street safe all day | The old page showed it; the redesign dropped it |
| `/hosting` | `share_of_draws_failed_by_level`: how the share of failing draws grows with adoption | A curve, shown today only as three quantiles |
| `/street`, `/whatif` | `losses_kwh`, `reactive_loss_kvarh`, `max_vuf_pct` (voltage unbalance), `max_neutral_a`, `inverter_kvarh`, `pv_kwh`, `reverse_flow_steps`, `battery_throughput_kwh` | The cost accounting and limits of the plan (wire loss, reactive loss, unbalance, neutral) |
| `/street` | `line_loading_pct` per wire and step | Wires are never coloured by loading, so an overloaded wire is invisible |
| `/street` | `line_neutral_a` per wire | The neutral is drawn as a conductor, but its current per wire is not shown |
| `/fixes` | `cost.battery_throughput_kwh`, `n_scenarios` | |
| `/transformers` | `metered` (and what it means) | Cannot be set or seen |
| `/rx-map` | `r_over_x` | The ratio that explains the table |
| `results.json` | The headline tournament sentences (`tournament_15_may_2019`), no longer shown | |

### 3.2 Accepted by the API but with no control on the dashboard

| Parameter | What it would do |
| --- | --- |
| `network` on every route; `/networks` is never called | Choose among the five street types. Today only the benchmark street can be opened on Tomorrow, Fixes, Planning and Try a change; the other four appear only in the transformer ranking |
| `adoption` on `/headroom`, `/meter-sites`, `/rx-map`, `/whatif` | The share of homes with solar. Planning is fixed at 30% and Try a change at 100%; the old What-if page had this control and the redesign dropped it |
| `fix` on `/risk` and the whole `/simulate` route | Redraw the risk strip with a fix applied |

### 3.3 Built in the engine or models, with no API route (so no screen)

| Feature | Where | What is missing |
| --- | --- | --- |
| Cumulative connection check and the 10 kW feasibility-study exemption | `engine/headroom.py` (`cumulative_check`, `exempt_below_kw`) | The `/connection-check` body takes neither `existing` systems nor the threshold |
| Utility onboarding (feeder, homes, meter CSV validators and ingest) | `engine/onboard.py`, `scripts/onboard.py` | A command-line tool only: no upload or validation screen, which is how a utility would load its own street |
| Cold-start solar forecast for new rooftops (plan item B4) | `ml/coldstart.py` | No runtime code imports it (only its test) |
| Grounded explanations | `engine/explain.py` | `explain_risk` and `explain_verdict` feed the printable report only; `explain_fix` and the Hindi templates are not served |

| Reliability backtest bins | `data/results/reliability_*.json`, `risk_calibration_*.json` | Not in `/results`; the Proof page cannot draw the reliability diagram the plan asks for |

| Phase assignment of the homes (assumed round-robin) | the network builder | Cannot be inspected or changed; a utility's real phases only come in through onboarding |
